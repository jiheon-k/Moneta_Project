# Moneta 프런트엔드

React + TypeScript + Vite로 만든 한국어 가계부 화면입니다.
회원가입·로그인 후 계좌·카테고리를 관리하고 지출을 등록해 거래 내역과 잔액을 확인할 수 있습니다.

개발 협업 방식은 루트 AGENTS.md와 최신 사용자 지시를 따릅니다.

## 실험용 화면

루트에서 `./gradlew bootRun --args='--spring.profiles.active=demo'`를 실행한 뒤,
이 폴더에서 `npm run dev:demo`를 실행하면 http://localhost:5174 에서 체험할 수 있습니다.
예제 계정은 `demo_user` / `moneta-demo-1234`입니다.
아래 일반 실행 방법은 기존 MySQL 백엔드를 사용하는 경우입니다.

## 실행

Node.js 24 LTS를 권장합니다. 이 작업에서는 Homebrew로 `node@24`를 설치했습니다.
터미널에서 `node`가 없다면 먼저 다음 명령을 실행하세요.

```bash
export PATH="/opt/homebrew/opt/node@24/bin:$PATH"
```

프로젝트 루트에서:

```bash
cd frontend
npm ci
npm run dev
```

화면: http://localhost:5173
기본 백엔드 주소: http://127.0.0.1:8080
백엔드는 기존 방식대로 별도 터미널에서 실행합니다.

Vite가 `/api/...` 요청을 Spring Boot의 `/...`로 전달하므로
백엔드 CORS나 보안 설정을 바꿀 필요가 없습니다.
다른 백엔드 주소를 쓰려면 `.env.example`을 `.env.local`로 복사하고
`API_PROXY_TARGET`을 변경한 뒤 Vite를 다시 실행하세요.

## 구현 범위

- 한국어 로그인·회원가입 폼과 모바일 대응 레이아웃
- 비밀번호 표시 전환, 확인 입력, 가입 규칙에 따른 필드 검증
- 중복 아이디, 로그인 실패, 연결 실패에 대한 안내
- 쿠키 기반 세션 인증과 CSRF 토큰 자동 전달
- 로그인 상태 복원 및 로그아웃
- 요청 중 중복 제출 방지
- 비밀번호·CSRF 토큰을 localStorage/sessionStorage에 저장하지 않음
- 계좌 생성, 본인 계좌 목록에서 선택·조회, 이름·유형·초기 잔액 수정, 삭제
- 계좌별 기간·유형 조건 거래 조회 (시작일 포함, 종료일 제외)
- 카테고리 목록 조회·추가·이름 수정·삭제 (`/categories`)
- 삭제 확인, 요청 실패 안내, 세션 만료 시 로그인 화면 전환

지출 등록은 `/expenses`를 사용합니다. 금액은 1원~1조 원 정수, 날짜는 오늘까지,
내용은 최대 255자, 카테고리는 생략할 수 있습니다. 저장 후 해당 날짜의 내역과 잔액을 갱신합니다.
공통 카테고리는 수정·삭제 버튼을 비활성화합니다. 거래가 연결된 계좌·카테고리 삭제와
거래 등록 후 초기 잔액 변경은 서버에서 409 응답으로 거절합니다.

## 인증 요청 흐름

1. 페이지를 열면 `/api/auth/me`로 현재 로그인 상태를 확인합니다.
2. 변경 요청 전에 `/api/auth/csrf`에서 현재 세션의 토큰을 받습니다.
3. 응답의 `headerName`을 헤더 이름으로, `token`을 값으로 전송합니다.
4. 가입 성공 시 비밀번호를 지우고 로그인 폼으로 전환합니다.
5. 로그인 성공 시 계좌·카테고리 관리 화면으로 전환합니다.
6. 로그아웃할 때 새 토큰을 받아 요청합니다. 서버 성공 응답 후 로그인 폼으로 돌아갑니다.
7. CSRF가 다른 탭에서 갱신된 경우 한 번만 새 토큰으로 재시도합니다.

서버 검증이 최종 기준이며, 프런트엔드 검증만으로 가입을 허용하지 않습니다.
쿠키는 브라우저가 같은 출처의 요청에 전달합니다.

## 검증

```bash
npm test
npm run build
```

- Vitest로 API 처리, 입력값 검증, 실제 React DOM의 폼과 상태 전환을 검사합니다.
- 실제 Spring Boot 인증 API를 임시 H2 메모리 DB로 실행해 Vite 프록시를 통한
  가입·중복·로그인 실패·세션 유지·세션 ID 교체·CSRF 갱신·로그아웃을 확인했습니다.
- 개발 MySQL에는 테스트 계정이나 스키마 변경을 적용하지 않았습니다.
- 2026-11-18 실험용 H2 파일 DB와 연결한 브라우저에서 로그인·계좌 선택·지출 등록·잔액 반영과 화면을 확인했습니다.

프로덕션 빌드는 `dist/`에 생성됩니다. 배포는 수행하지 않았습니다.
실제 배포 시 프런트엔드를 제공하는 서버에서도 `/api`를 백엔드로 전달하도록 설정해야 합니다.
Vite의 프록시는 개발 서버 및 로컬 미리보기용입니다.

## 가계부 화면 검증

가계부 API의 요청 필드, CSRF를 포함한 PATCH·DELETE, 빈 200 응답, 오류 처리와
화면의 계좌 생성·조회 실패·입력 검증·카테고리 추가·삭제 확인·세션 만료를 모의 응답으로 검사합니다.
거래 목록 키 `tList`는 현재 백엔드 DTO를 Jackson으로 직렬화하여 확인했습니다.
계좌·카테고리·지출 API는 H2 통합 테스트로 확인했으며, 실제 MySQL 검증은 수행하지 않았습니다.
최종 프런트엔드 테스트는 61개 통과, 빌드 성공입니다. 기존 Date 렌더링 관련 lint 경고 2개는 남아 있습니다.
